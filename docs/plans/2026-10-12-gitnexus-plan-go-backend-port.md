## 1. Objective

Make Go the sole runtime and distribution path for source discovery and parsing, canonical modeling, T3 target operations, safety and recovery, CLI, and Bubble Tea TUI. This is a hard fork: no npm compatibility launcher or user migration path is required. Preserve user-facing importer behavior and existing T3 data compatibility where practical; redesign internal interfaces and the v2 write/projection path where Go ownership requires it. Do not alter T3-owned schema migrations or write unvalidated formats.

## 2. Current Behaviour

[verified] The Go command in `cmd/t3-import-tui/main.go` currently invokes the installed `t3-import bridge` command for every backend operation; `src/bridge.ts` version 1 delegates to `src/workflow.ts` and existing TypeScript source/target modules. The TUI is therefore not yet a Go importer; the TypeScript/npm path will be removed as part of this hard fork.

[verified] TypeScript owns Codex and Claude discovery/parsing (`src/sources/codex.ts`, `claude.ts`, `codexAppServer.ts`), canonical data types (`src/core/types.ts`), CLI output/exit compatibility (`src/cli.ts`), and all T3 interactions (`src/target/*`). Codex discovery combines stable rollout JSONL with optional app-server metadata; Claude parsing reconstructs transcript parent/leaf graphs and normalizes compaction/retry history.

[verified] The target layer supports legacy T3 migrations 40–53 and a separately validated pinned v2 profile. Legacy imports append events and runtime rows; v2 import, sync, and replacement use a bundled native EventSink helper. Operations rely on closed-T3 checks, SQLite locking, verified backups, staged assets, idempotency ledgers/checkpoints, conflict detection, and cache reset.

[verified] The public surface includes list/show/doctor/cache/import/sync/replace, JSON envelopes and exit codes, plus interactive Ink; the Bubble Tea TUI currently depends on the npm backend, which the Go hard fork removes. `package.json` requires Node 22+ and ships the CLI.

## 3. Relevant Architecture

Preserve its serialized values, optional fields, timestamps, IDs, attachment representation, turn states, and outcome vocabulary as a Go contract before porting parsers.

[verified] Source adapters are selected through `src/sources/index.ts`; target profile selection and provider settings are centralized in `src/target/config.ts` and `schema.ts`. `importer.ts` is a high-connectivity target module used by sync and v2 operations for planning, locks, backups, assets, and native helper calls.

## 6. Proposed Changes

- **Go domain model and wire compatibility** (`internal/domain/`, `internal/contract/`): encode the canonical conversation, outcome, checkpoint, result, and JSON CLI shapes. Add golden fixtures from existing TS outputs. Keep schema version 1 result envelopes and exact exit-code semantics until a separately versioned change is approved.
- **Go source adapters** (`internal/source/codex/`, `internal/source/claude/`, `internal/source/appserver/`): implement stable JSONL reads/fingerprints, tolerant file walking with per-file diagnostics, Codex rollout parsing plus app-server JSON-RPC fallback/enrichment, Claude graph/sidechain/compaction/retry normalization, workspace filtering, incomplete-turn policy, and supported attachment decoding. Expose the same discover/load capability with injected filesystem/process seams for tests.
- **Go target configuration and safety** (`internal/target/config/`, `schema/`, `runtime/`, `backup/`, `assets/`, `ledger/`, `cache/`, `launch/`): port target path resolution, provider-instance/model selection, live-T3 checks, profile/migration validation, process lock, verified SQLite backups, safe staged asset materialization, recovery ledger/checkpoints, cache backup/reset/rollback, and launch behavior. Select a cross-platform SQLite driver only after verifying CI and packaging constraints; do not add schema migrations.
- **Legacy T3 adapter** (`internal/target/legacy/`): port event planning, compaction budget, import, sync, replacement, read-only previews, reconciliation and transactions. Keep writes to the same supported tables and fields, and continue failing closed for unknown profiles or projection backlog.
- **Pinned v2 adapter** (`internal/target/v2/`): port v2 schema recognition, event planning, adoption, old-ledger upgrade reconciliation, history verification, continuation identities, compare-and-set attach, sync, replacement, assets, backup and recovery. Implement a Go-owned adapter that writes the pinned event contract transactionally and produces verified readback/projection state without a TypeScript helper. Preserve T3-owned schema and avoid unvalidated formats; if matching the existing EventSink requires a redesigned Go projector, document its invariants and test it against pinned synthetic T3 homes before release.
- **Operation coordinator and CLI** (`internal/app/`, `cmd/t3-import/`, `cmd/t3-import-tui/`): make TUI and CLI call the same Go workflow implementation. Port list/show/doctor/cache/import/sync/replace, dry-run/yes/non-interactive behavior, selection revalidation, JSON/plain output, exit codes, progress/cancellation rules, and optional T3 launch. Keep Bubble Tea model behavior and mouse support while replacing bridge calls with internal async commands.
- **Go distribution and cleanup** (`go.mod`, `.github/workflows/ci.yml`, `README.md`, `package.json`, `src/**`): make Go builds, tests, and `go install` the supported release path. Use TypeScript fixtures/oracle during development, then remove the bridge, workflow, Ink UI, TS backend and npm publishing machinery from the hard fork. No npm launcher or user migration path is required.

## 7. Implementation Sequence

1. **Capture behavior and data contracts.** Record representative canonical JSON, CLI output and exit codes, checkpoint IDs/hashes, ledger records, and T3 database effects from synthetic fixtures. Add Go golden tests and a parity matrix for both providers and target profiles. TypeScript is a temporary source of fixtures, not a required supported runtime.
2. **Establish Go module seams.** Add domain/result types and internal interfaces for source adapters, target profile adapters, and workflow coordinator. Add deterministic ID, timestamp, stable JSONL, path, and checkpoint compatibility tests. Decide SQLite driver and Windows/macOS/Linux build approach.
3. **Port read-only source foundations.** Implement JSONL stability/file walking and Codex discovery/rollout parsing, then app-server enrichment; implement Claude discovery and graph normalization. Compare Go outputs with TS golden fixtures, including malformed/partial inputs and diagnostic outcomes.
4. **Port target read-only paths.** Implement config/provider selection, live runtime inspection, schema/profile validation, doctor, list/show previews, and dry-run planning for legacy and v2. Enable writes after previews and corresponding synthetic DB readback fixtures match.
5. **Port legacy writes.** Add locking, verified backup and asset staging, import transaction, sync/reconciliation, replacement, ledger recovery, cache reset, and launch. Run the existing compatibility matrix and failure injection before enabling the Go CLI for real writes.
6. **Port v2 with a Go-owned storage design.** Implement the pinned event contract, transactional writes, projection/readback, rollback, adoption, upgrade mapping, continuation, sync and replacement in Go. Redesign internal operations where the current native-helper shape does not fit Go; validate results against pinned synthetic T3 homes and existing acceptance scenarios.
7. **Switch the TUI and add the native Go CLI.** Remove bridge subprocess calls from the Bubble Tea model; route CLI and TUI through shared Go operations. Preserve review/confirmation and refusal to cancel an active confirmed write.
8. **Run differential and native acceptance.** Execute identical synthetic scenarios against TS oracle fixtures and Go, compare normalized results/database effects, then run cross-platform builds and isolated T3 acceptance.
9. **Remove TypeScript and npm runtime.** Delete TS bridge/backend, Ink UI, npm publishing configuration and Node-only compatibility gates. Keep only portable fixture data and documentation needed to validate supported T3 profiles; publish/install the Go commands with `go install` as the default.

## 9. Risk and Impact Analysis

- **Highest risk: v2 event and projection behavior.** The current path uses a bundled TypeScript helper and verifies post-write projections. Go will own a replacement writer and projection/readback path. A careless design can make events invisible or corrupt state; validate each event and readback invariant against pinned fixtures before release.
- **Semantic drift in provider parsing.** Codex rollout rows and app-server metadata can disagree; Claude transcripts contain graph, branch, retry, compaction, and sidechain edge cases. Golden and differential fixture tests must cover the complete supported semantics before deleting TS parsers.
- **Data-loss/recovery risk.** Backup ordering, lock scope, staged attachments, atomic legacy transactions, v2 readback, ledger updates, and cache reset rollback must remain ordered as today. Confirmed writes must not be cancelled halfway by TUI teardown.
- **Compatibility risk.** JSON keys, optional/null behavior, output stream split, command flags, exit codes, IDs, checkpoint hashes, and ledger format remain user-facing contracts. npm installations are out of scope. Pin behavior with fixtures before migration.
- **Platform/package risk.** Go 1.27.2 builds on three OSes; SQLite driver CGO, native helper, file permissions, process liveness, and Electron cache paths have platform-specific behavior. Test clean consumer installs on Windows/macOS/Linux.
- **Scope risk.** Porting all v2 behavior is much larger than the existing Go UI. Sequence by user-visible capability and do not declare completion while a TypeScript subprocess still performs importer or T3 operations.
- **Observability.** Preserve structured per-session outcomes and include target, backup paths, operation type, counts, and recovery action in CLI/TUI results. Avoid logging transcript or attachment contents.
